## 一、先说结论

如果你只想看结果：

1. 目标站用了**瑞数 5 代**，它会检测浏览器是否被**调试器** attach。
2. Playwright、Puppeteer、DrissionPage、Selenium 的 CDP 模式、以及你按下的 **F12**，都会开启 CDP 的 `Debugger` 域。
3. `Debugger` 一开，页面里的 `debugger;` 语句就不再是空操作，会真的暂停/被拦截，导致挑战脚本的**计时、调用栈、`Error.stack`** 全部异常。
4. 瑞数不会当场报错，而是**静默作废刚算出来的 cookie**。服务端校验失败 → 412 → 400（body 是 6 字节空响应）。
5. 解决办法：**换一个没有 CDP Debugger 通道的浏览器自动化协议** —— Firefox + **WebDriver BiDi**（本文用 `ruyipage`）。

一句话对照：

```text
普通浏览器     : debugger; 是空操作 → 正常算 cookie → 200
Chrome + CDP  : debugger; 被 attach → 计时/栈异常 → cookie 作废 → 412 → 400
Firefox + BiDi: 没有 Debugger 通道 → debugger; 仍是空操作 → 正常 cookie → 200
```

## 二、现象：手动能开，脚本就 400

### 2.1 现场日志

```text
GET  https://xxx.example.com/search          → 412（挑战页）
GET  https://xxx.example.com/search          → 400
POST https://xxx.example.com/api/token       → {"code":400,"msg":"\r\n\r\n\r\n"}
GET  https://xxx.example.com/api/user/info   → 400
```

关键特征：

- 400 的响应体非常短，常见就是 `\r\n\r\n\r\n`（6 个字节）；
- 同一个账号、同一个 IP，**手动打开浏览器完全正常**；
- 换新 profile、删 cookie、换 UA 都没用；
- 有时候停几分钟再跑又能成功一次，然后继续 400。

### 2.2 最容易误判的地方

很多人看到 412 就开始怀疑：

1. cookie 是不是算错了？
2. 是不是有签名参数没逆向？
3. IP 是不是被拉黑了？
4. 是不是要代理池？

先别急。这三条我都替你排除了，往下看。

## 三、三个常见误判，先排除

### 3.1 不是 cookie 算错

如果 cookie 真的算错，手动浏览器也应该失败。但手动浏览器**每次都正常**，
而且抓包能看到挑战 JS 正常执行、正常写入 cookie。

### 3.2 不是签名/参数错

把浏览器里真实发出的请求原样复制（URL、Header、Body、Cookie 全部一致），
用 `requests` 重放仍然是 400。说明问题不在参数，而在**请求之前的浏览器环境**。

### 3.3 不是 IP 被封

如果是 IP 封禁，手动浏览器也会失败。实际是手动 200、脚本 400，
同一个出口 IP、同一个时间点，唯一变量是**浏览器是怎么被启动/连接的**。

> 这一步最关键：把「账号、IP、cookie、参数」都固定住，只剩「浏览器驱动方式」在变。
> 一旦你这么做了，答案会自己浮出来。

## 四、排查方法论：把变量降到最小

思路：不用 Playwright、不用 DrissionPage，自己写一个**最小 CDP 客户端**，
只做三件事：

1. 启动 Chrome，开一个远程调试端口；
2. 连接页面 WebSocket；
3. **按需** enable 不同的 CDP 域，然后导航到目标页，看状态码。

这样就能精确知道是哪个域触发了风控。

### 4.1 启动一个干净的 Chrome

```bash
# Windows（路径按自己机器改）
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --remote-debugging-port=9222 ^
  --user-data-dir=D:\tmp\cdp_test_profile ^
  --no-first-run --no-default-browser-check ^
  about:blank
```

```bash
# Linux
google-chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/cdp_test_profile \
  --no-first-run --no-default-browser-check \
  about:blank
```

> 注意：不要用你日常的 Chrome profile，避免污染登录态。
> 也不要在这台 Chrome 上按 F12。

### 4.2 最小 CDP 客户端

安装依赖：

```bash
pip install requests websocket-client
```

代码（`cdp_probe.py`）：

```python
# -*- coding: utf-8 -*-
"""最小 CDP 客户端：只导航 + 取文本，用来做「域对照实验」"""
import json
import time

import requests
from websocket import create_connection

TARGET_URL = "https://xxx.example.com/search"


def probe(enable_domains=(), timeout=20):
    # 1) 拿到页面 target 的 ws 地址
    targets = requests.get("http://127.0.0.1:9222/json", timeout=5).json()
    page = next(t for t in targets if t["type"] == "page")

    ws = create_connection(page["webSocketDebuggerUrl"], timeout=timeout)
    seq = 0

    def call(method, params=None, wait=True):
        nonlocal seq
        seq += 1
        msg_id = seq
        ws.send(json.dumps({
            "id": msg_id,
            "method": method,
            "params": params or {},
        }))
        if not wait:
            return None
        deadline = time.time() + timeout
        while time.time() < deadline:
            try:
                msg = json.loads(ws.recv())
            except Exception:
                return None
            if msg.get("id") == msg_id:
                return msg
        return None

    # 2) 必开的 Page 域（导航需要）
    call("Page.enable")

    # 3) 按参数 enable 待测域
    for domain in enable_domains:
        call(f"{domain}.enable")

    # 4) 导航
    call("Page.navigate", {"url": TARGET_URL})

    # 5) 等一会儿，取页面文本
    time.sleep(8)
    result = call("Runtime.evaluate", {
        "expression": "document.body ? document.body.innerText.slice(0,200) : ''",
        "returnByValue": True,
    })
    ws.close()

    if not result:
        return None
    value = result.get("result", {}).get("result", {}).get("value", "")
    return value


if __name__ == "__main__":
    cases = [
        (),
        ("Runtime",),
        ("Network",),
        ("DOM",),
        ("Log",),
        ("Debugger",),      # 重点
    ]
    for domains in cases:
        label = "+".join(domains) or "(不 enable 任何域)"
        text = probe(domains)
        print(f"{label:>20} -> {repr((text or '')[:80])}")
```

### 4.3 实验结果

同一台机器、同一个 Chrome、同一个 IP、同一个账号：

| 开启的 CDP 域 | 结果 |
| --- | --- |
| 不 enable 任何域 | **200，页面正常** |
| Runtime | 200 |
| Network | 200 |
| DOM | 200 |
| Log | 200 |
| **Debugger** | **空白 / 400** |

把 `Debugger` 换成其他任何域都正常，**只有 Debugger 会挂**。

> 注意：enable `Debugger` 之后，页面可能直接停在 `debugger;` 处，
> `Page.navigate` / `Runtime.evaluate` 会一直等到超时——这本身就是被检测的表现，
> 不是你的客户端写错了。实验时给调用加上超时、失败就关掉 WebSocket 即可。

> 如果你复现出这张表，恭喜，不用再逆 JS 了。问题不是 cookie，
> 是浏览器被调试这件事本身。

### 4.4 为什么很多人没做这一步

因为主流框架把 CDP 连接封装得很深：

- Playwright 启动时就会 enable 一批域；
- DrissionPage 连接时也会启用；
- 你自己写的脚本如果用了 `run_cdp` 调试，也可能顺手开了 `Debugger`。

大家默认「CDP 只是控制浏览器」，没意识到它同时**改变了页面 JS 的运行环境**。

## 五、原理：`Debugger.enable` 到底改变了什么

### 5.1 `debugger;` 语句的语义

页面里写：

```js
debugger;
```

- **没有调试器 attach**：这是空操作，几乎不耗时；
- **有调试器 attach**：执行会在这里暂停，等待调试器 `resume`。

瑞数的挑战脚本里就有类似的语句（不止一处），并用它做自检。

### 5.2 计时检测

简化后的检测逻辑：

```js
var t0 = performance.now();
debugger;
var dt = performance.now() - t0;

if (dt > 50) {
    // 有调试器 / 被执行环境干扰
    mark_suspicious();
}
```

正常浏览器里 `dt` 通常小于 1ms；一旦被调试器暂停，`dt` 会变成几百毫秒甚至几秒。

### 5.3 调用栈与 `Error.stack`

```js
function check() {
    var stack = new Error().stack || "";
    // 某些调试器会在栈里留下额外帧 / 改变格式
    if (/debugger|inspector/i.test(stack)) mark_suspicious();
}
```

CDP 的 Debugger 域开启后，V8 的 inspector 状态改变，`Error.stack` 的内容和格式
也可能出现可观测差异。

### 5.4 断点/暂停本身的可观测副作用

- `Debugger.enable` 之后，JS 引擎会维护断点、黑盒、跳过规则等状态；
- 页面可以通过 `Function.prototype.toString`、`console` 行为、异常捕获等
  间接感知「环境不干净」；
- 瑞数这类厂商会把这些信号综合成一个「环境分」。

### 5.5 瑞数的策略：不报错，静默作废

这点很关键：检测到异常后，它**不会**抛一个显眼的异常，而是：

1. 照常执行挑战脚本；
2. 但生成一个「标记为异常」的 cookie 或 token；
3. 服务端校验这个值 → 不通过 → **412**（要求重新挑战）；
4. 再次请求仍然不通过 → **400**（body 只有 `\r\n\r\n\r\n`）。

所以你在网络面板里看到的是「挑战跑了、cookie 也写了，但就是 400」，
非常容易误判成「cookie 算错了」。

## 六、为什么 F12 也会中招

DevTools 本身就是一个调试器。你按下 F12 的瞬间：

- `Debugger` 域被启用；
- 页面里的 `debugger;` 开始真的暂停；
- 瑞数的自检立即发现异常。

**验证方法**：打开目标站，按 F12，刷新页面。大概率会看到 400 / 空白。
关掉 F12 再刷新，恢复正常。

这也是为什么很多同学说「我明明没写自动化，只是开了控制台看了一下，就被封了」。

> 调试期间如果真的需要看网络，优先用抓包工具（Charles / Fiddler / mitmproxy）
> 或者外部日志，不要在自动化窗口里开 DevTools。

## 七、为什么 requests / cookie 回放救不了

常见思路是：浏览器过完挑战，导出 cookie，然后用 `requests` / `curl_cffi` 直连。

对 Cloudflare 这类站点经常有效，但对瑞数通常无效，原因有三：

1. **cookie 是动态的**：名字随机、值由挑战脚本现算，且和本次挑战的 nonce 绑定。
2. **服务端会二次校验**：不是只看 cookie 是否存在，而是校验它和请求上下文是否匹配。
3. **挑战参数挂在 URL 上**：接口路径里会出现随机名参数（如 `?aB3dE9=x`），
   一次有效，重放就失效。

所以这类站点的结论是：**必须保留一个真实浏览器进程，由它发请求**。
不要试图「浏览器拿 cookie + HTTP 全速抓取」，这条路线在瑞数 5 代上走不通。

## 八、方案选型：为什么是 Firefox + BiDi

### 8.1 可选方案对比

| 方案 | 底层协议 | 是否有 Debugger 域 | 实测 |
| --- | --- | --- | --- |
| Playwright（Chromium） | CDP | 有 | 412 → 400 |
| Puppeteer | CDP | 有 | 412 → 400 |
| DrissionPage（Chrome） | CDP | 有 | 412 → 400 |
| Selenium（Chrome） | WebDriver + CDP（部分能力） | 可能启用 | 取决于配置，不稳定 |
| Selenium（Firefox） | WebDriver Classic / BiDi | 无 CDP | 理论可行，但 API 较弱 |
| **ruyipage（Firefox + BiDi）** | **WebDriver BiDi** | **无** | **200，稳定** |

### 8.2 Firefox 从 141 起已经移除了 CDP

这不是「绕」，而是**协议层就没有这条通道**：

- Firefox 141 彻底删除 CDP 支持；
- ruyipage 走的是 W3C 标准的 **WebDriver BiDi**；
- BiDi 的模块是 `browsingContext` / `script` / `input` / `network` / `storage` 等，
  **没有 `Debugger.enable`**。

所以页面里的 `debugger;` 仍然是无害的空操作，计时和调用栈都正常。

### 8.3 ruyipage 的额外好处

- 自带 Firefox 内核，`navigator.webdriver` 恒为 `false`；
- 输入走浏览器原生输入层，点击/键盘/拖拽是 `isTrusted` 事件；
- 支持元素截图、`localStorage` 读写、多标签页、网络拦截；
- API 风格接近 DrissionPage，迁移成本低。

> 如果你不想引入 ruyipage，理论上 Selenium + Firefox 也能避开 CDP Debugger，
> 但元素截图、BiDi 输入、多标签页管理都要自己补，工程成本更高。

## 九、环境准备

### 9.1 Python 版本

ruyipage 要求 **Python >= 3.9**。

```bash
python -V
```

如果是 Ubuntu 20.04 自带的 3.8，`pip install` 会直接报：

```text
ERROR: Package 'ruyipage' requires a different Python: 3.8.10 not in '>=3.9'
```

**不要**用 `--ignore-requires-python` 硬装。ruyipage 里大量使用 3.9+ 的运行时语法
（`list[str]` 这类注解在 3.8 里会直接抛
`TypeError: 'type' object is not subscriptable`），必须换 Python。

内网服务器没法装 Python 时，可以用 python-build-standalone 的独立
Python 3.11（解压即用，不需要 root）：

```bash
mkdir -p /opt/python3.11
tar -xzf cpython-3.11.17+*-x86_64-unknown-linux-gnu-install_only.tar.gz \
    -C /opt/python3.11 --strip-components=1
/opt/python3.11/bin/python3.11 -m venv venv311
source venv311/bin/activate
```

### 9.2 安装 ruyipage

```bash
pip install ruyiPage
python -m ruyipage install      # 下载配套 Firefox 内核（约 46MB 压缩 / 700MB 解压）
python -m ruyipage doctor       # 检查是否就绪
```

### 9.3 已经有系统 Firefox？

可以不装自带内核。ruyipage 的查找顺序是：

1. `launch(browser_path=...)` 显式指定

## 十一、工程化：把旧代码迁到 ruyipage

### 11.1 为什么需要适配层

如果你原来的代码是按 DrissionPage 写的，会大量出现这种选择器：

```python
page.ele(".btn operation")      # class 同时包含 btn 和 operation
```

DrissionPage 的 `.` 表示「class 属性包含」，ruyipage 的 `.` 是标准 CSS。
直接传会被解析成「`.btn` 下面的 `<operation>` 标签」，永远选不中。

适配层要做四件事：

1. **选择器翻译**：`.btn operation` → `css:.btn.operation`
2. **方法对齐**：`click()` → `click_self()`，`get_screenshot()` → `screenshot()`
3. **动作链对齐**：DP 的 `hold/move/release` 是逐条立即执行，
   ruyipage 是排队后统一 `perform()`
4. **JS 与按键对齐**：元素级 `run_js` 要包成函数；`input("...\n")` 要转成 `Keys.ENTER`

### 11.2 适配层代码（可直接用）

```python
# -*- coding: utf-8 -*-
"""DrissionPage 风格 -> ruyipage 的最小适配层"""
import time

from ruyipage import Keys


def translate(sel):
    if not isinstance(sel, str):
        return sel
    s = sel.strip()
    if not s:
        return s
    if s.startswith(("css:", "c:", "xpath:", "x:", "text:", "text=", "tag:")):
        return s
    if s.startswith(("#", "[", "*")):
        return "css:" + s
    if s.startswith(("/", "./")):
        return s
    if s.startswith("."):
        words = [w for w in s[1:].split() if w]
        if not words:
            return "css:body"
        if all(not w.startswith(".") for w in words):
            return "css:" + "".join("." + w for w in words)
        return "css:." + " ".join(words)
    return s


class Actions:
    def __init__(self, owner):
        self._o = owner

    def hold(self, ele=None):
        self._o.actions.hold(getattr(ele, "_el", ele))
        self._o.actions.perform()
        return self

    def move(self, offset_x=0, offset_y=0, duration=100):
        if 0 < duration < 5:            # DP 传秒，ruyipage 要毫秒
            duration *= 1000
        self._o.actions.move(int(round(offset_x)), int(round(offset_y)), int(duration))
        self._o.actions.perform()
        return self

    def release(self):
        self._o.actions.release()
        self._o.actions.perform()
        return self


class Element:
    def __init__(self, el):
        self._el = el

    def __bool__(self):
        try:
            return bool(self._el)
        except Exception:
            return False

    @property
    def text(self):
        try:
            return self._el.text or ""
        except Exception:
            return ""

    @property
    def html(self):
        try:
            return self._el.html or ""
        except Exception:
            return ""

    def attr(self, name):
        try:
            return self._el.attr(name)
        except Exception:
            return None

    def style(self, name):
        try:
            return self._el.style(name)
        except Exception:
            return ""

    @property
    def rect(self):
        return self._el.rect

    def click(self):
        self._el.click_self()
        return self

    def input(self, text, clear=True):
        text = str(text)
        enter = text.endswith("\n")
        body = text.rstrip("\r\n")
        if body:
            self._el.input(body, clear=clear)
        elif clear:
            try:
                self._el.clear()
            except Exception:
                pass
        if enter:
            self._el._owner.actions.press(Keys.ENTER).perform()
        return self

    def clear(self):
        try:
            self._el.clear()
        except Exception:
            pass
        return self

    def run_js(self, js):
        js = str(js).strip()
        if js.startswith(("function", "(", "async")):
            return self._el.run_js(js)
        return self._el.run_js("function(){" + js + "}")

    def ele(self, sel, timeout=None):
        return Element(self._el.ele(translate(sel), timeout=timeout))

    def eles(self, sel, timeout=None):
        return [Element(e) for e in self._el.eles(translate(sel), timeout=timeout)]

    def screenshot(self, as_bytes="png"):
        return self._el.screenshot(as_bytes=as_bytes)


class Tab:
    def __init__(self, obj):
        self._o = obj

    @property
    def tab_id(self):
        return self._o.tab_id

    @property
    def url(self):
        return self._o.url

    @property
    def title(self):
        return self._o.title

    @property
    def html(self):
        return self._o.html or ""

    @property
    def actions(self):
        return Actions(self._o)

    def get(self, url, timeout=20, wait="interactive"):
        self._o.get(url, wait=wait, timeout=timeout)
        return self

    def ele(self, sel, timeout=None):
        return Element(self._o.ele(translate(sel), timeout=timeout))

    def eles(self, sel, timeout=None):
        return [Element(e) for e in self._o.eles(translate(sel), timeout=timeout)]

    def run_js(self, js):
        js = str(js).strip()
        if "return" in js and not js.startswith(("function", "(")):
            return self._o.run_js(js, as_expr=False)
        return self._o.run_js(js, as_expr=True)

    def screenshot(self, as_bytes="png", full_page=False):
        return self._o.screenshot(full_page=full_page, as_bytes=as_bytes)

    def close(self):
        self._o.close()


class Page(Tab):
    @property
    def latest_tab(self):
        return Tab(self._o.latest_tab)

    def get_tabs(self):
        return [Tab(t) for t in self._o.get_tabs()]

    def quit(self):
        self._o.quit()

    def close(self):
        self._o.close()
```

> 这段代码解决 90% 的迁移问题。剩下 10% 通常是「某个元素必须用 JS 点」
> 或「新标签页切换」，下面会讲。

## 十二、登录：OAuth 授权码模式的坑

### 12.1 不要直接打开登录页

很多站点的登录是「统一身份认证平台」，业务流程是 OAuth 授权码：

```text
业务站 /oauth/authorize?client_id=xxx&redirect_uri=业务站/init
        ↓ 未登录
统一登录页 → 账号密码 + 验证码
        ↓ 登录成功
业务站 /init?code=xxxx
        ↓ 前端用 code 换 token
localStorage.setItem("token", jwt)
```

如果你直接打开「统一登录页」，登录成功后只会回到**统一身份平台首页**，
业务站仍然是未登录状态（页头还挂着「登录/注册」，`localStorage.token` 为空）。

正确做法：**从业务站的 `authorize` 地址进入**，让 OAuth 流程自己把 `code` 带回来。

```python
AUTH_URL = (
    "https://xxx.example.com/oauth/authorize"
    "?response_type=code&scope=openid"
    "&client_id=xxx"
    "&redirect_uri=https://xxx.example.com/init"
)
page.get(AUTH_URL)
```

### 12.2 登录态怎么判断

不要只看 URL。可靠的三件套：

```python
def logged_in(page):
    # 1) 不在登录页
    if "login" in str(page.url).lower():
        return False
    # 2) 页头没有「登录/注册」入口
    if page.eles("css:.login-entry", timeout=1):
        return False
    # 3) localStorage 里有 token（或页面上有用户菜单）
    if page.run_js('return localStorage.getItem("token")'):
        return True
    return bool(page.ele("css:.user-menu", timeout=2))
```

> 只判断 URL 很容易误判：很多 SPA 在页面还没渲染完时 URL 就已经是首页了。

### 12.3 滑块验证码

滑块通用结构：

```html
<div class="verify-img-panel"><img src="data:image/png;base64,..."></div>
<div class="verify-sub-block"><img src="data:image/png;base64,..."></div>
<div class="verify-move-block"></div>
```

识别思路：

1. 两张图都是 data URI，直接 base64 解码；
2. 滑块图经常是 RGBA，带透明通道——**用 alpha 当掩码**；
3. 用 `TM_CCORR_NORMED` + 掩码做模板匹配，找缺口 x；
4. 缩放比 = 显示宽度 / `naturalWidth`，拖拽距离要乘这个比例。

```python
import base64
import re
from io import BytesIO

import cv2
import numpy as np
from PIL import Image


def decode(b64):
    if "," in b64:
        b64 = b64.split(",", 1)[1]
    img = Image.open(BytesIO(base64.b64decode(b64)))
    alpha = np.array(img.split()[-1]) if img.mode in ("RGBA", "LA") else None
    rgb = cv2.cvtColor(np.array(img.convert("RGB")), cv2.COLOR_RGB2BGR)
    return rgb, alpha


def find_gap(bg, sl, alpha):
    bg_gray = cv2.cvtColor(bg, cv2.COLOR_BGR2GRAY)
    sl_gray = cv2.cvtColor(sl, cv2.COLOR_BGR2GRAY)
    if alpha is not None and alpha.shape[:2] == sl_gray.shape[:2]:
        mask = (alpha > 10).astype(np.uint8) * 255
        if mask.sum():
            res = cv2.matchTemplate(bg_gray, sl_gray, cv2.TM_CCORR_NORMED, mask=mask)
        else:
            res = cv2.matchTemplate(bg_gray, sl_gray, cv2.TM_CCOEFF_NORMED)
    else:
        res = cv2.matchTemplate(bg_gray, sl_gray, cv2.TM_CCOEFF_NORMED)
    res = np.nan_to_num(res, nan=0, posinf=0, neginf=0)
    _, score, _, loc = cv2.minMaxLoc(res)
    return loc[0], score
```

拖拽要点：

- 轨迹要有中间步骤，先加速后减速，总和严格等于目标距离；
- 最后轻微滑过头再回正，更像人手；
- **成功判断不要只看页面有没有「验证成功」字样**，很多站点成功后直接收起面板，
  以 `.verify-img-panel img` 消失为准。

```python
def solve_slider(page):
    bg_el = page.ele("css:.verify-img-panel img", timeout=2)
    sl_el = page.ele("css:.verify-sub-block img", timeout=2)
    if not bg_el or not sl_el:
        return False

    bg, _ = decode(bg_el.attr("src") or "")
    sl, alpha = decode(sl_el.attr("src") or "")
    gap_x, score = find_gap(bg, sl, alpha)

    ratio = 1.0
    try:
        w = float(re.sub(r"[^0-9.]", "", bg_el.style("width") or "") or 0)
        natural = int(bg_el.run_js("return this.naturalWidth") or 0)
        if w and natural:
            ratio = w / natural
    except Exception:
        pass

    distance = max(1.0, gap_x * ratio)
    n = 30
    weights = [0.25 + 3.0 * np.sin(np.pi * (i + 0.5) / n) ** 0.8 for i in range(n)]
    total = sum(weights)
    tracks = [max(1, int(round(distance * w / total))) for w in weights]
    tracks[-1] += int(distance) - sum(tracks)

    handle = page.ele(".verify-move-block")
    if not handle:
        return False
    page.actions.hold(handle)
    time.sleep(0.4)
    for t in tracks:
        page.actions.move(offset_x=t, offset_y=np.random.randint(-2, 3), duration=0.05)
        time.sleep(0.01)
    page.actions.move(offset_x=3, duration=0.05)
    page.actions.move(offset_x=-3, duration=0.05)
    time.sleep(0.3)
    page.actions.release()
    time.sleep(2)

    if "验证成功" in (page.html or "") or "验证通过" in (page.html or ""):
        return True
    return not page.ele("css:.verify-img-panel img", timeout=0.5)
```

```python
    ap.add_argument("--json", action="store_true")
    args = ap.parse_args()

    page = Page(launch(
        user_dir="./xxx_firefox",
        headless=False,
        close_on_exit=True,
        window_size=(1920, 1080),
        timeout_base=15,
        timeout_page_load=60,
    ))
    try:
        page = ensure_login(page)
        result_tab = search(page, args.kw)
        if isinstance(result_tab, str) or result_tab is None:
            print("无结果 / 需要登录")
            return
        fields, img = read_detail(page, result_tab)
        out = {"found": bool(fields), "fields": fields, "img_len": len(img or "")}
        if args.json:
            print(json.dumps(out, ensure_ascii=False, indent=1))
        else:
            for k, v in fields.items():
                print(f"{k} = {v}")
    finally:
        page.quit()


if __name__ == "__main__":
    main()
```

> 说明：选择器（`.search-input`、`.result-row`、`.detail-panel` 等）都是占位示例，
> 换成你自己站点的即可，**逻辑和坑位是通用的**。

## 十五、踩坑合集

| 坑 | 现象 | 解决 |
| --- | --- | --- |
| 导航 30 秒超时 | `browsingContext.navigate (30s)`，但页面其实已加载 | `wait="interactive"`，别用 `complete` |
| 滑块总失败 | 匹配度很高但过不了 | 确认缩放比方向（显示/原图）；成功以面板消失为准 |
| 纯色拼图匹配错位 | 缺口 x 偏到背景平坦区 | 用 alpha 掩码 + `TM_CCORR_NORMED`，或白色描边轮廓 |
| 登录了但业务站未登录 | URL 是登录页/门户首页，token 为空 | 从业务站 OAuth authorize 入口进，不要直开统一登录页 |
| token 突然消失 | 偶发 400 后变成未登录 | 接口报错时前端会跳 `/init` 并删 token，重登即可 |
| 整站 400 | 所有请求都 400，停一会儿又好了 | 频率规则，退避 30~60 秒，别 2 秒猛刷 |
| `Enter` 报错 | `Expected "value" to be a single code point` | 用 `Keys.ENTER`，不要传字符串 `"Enter"` |
| 元素 `run_js` 报错 | 传了 `this.value=''` 这种语句 | ruyipage 需要函数声明，包成 `function(){...}` |
| 选择器选不中 | `.btn operation` 被当 CSS 后代 | 翻译成 `.btn.operation` |
| Python 3.8 装不上 | `requires a different Python` | 用 3.9+（内网可用独立 3.11） |
| snap Firefox 起不来 | profile 在 `/opt` 被拒绝 | profile 放 `$HOME` |
| profile 被锁 | 第二个进程启动失败 | 同一 profile 只允许一个进程 |
| 无中文字体 | 截图中文变方块 | 装 `fonts-noto-cjk` |
| 无图形环境 | `Cannot open display` | `xvfb-run` 或 VNC |
| F12 调试就 400 | 开了 DevTools | 自动化窗口里不要开 F12 |

## 十七、FAQ

**Q1：能不能用 Selenium + Firefox？**

理论上可以，Selenium 的 Firefox 驱动走 WebDriver，不依赖 CDP Debugger。
但元素截图、BiDi 输入、多标签页、`localStorage` 读写都要自己补，
而且不同版本 Firefox 的 BiDi 支持差异较大。ruyipage 相当于把这些封装好了。

**Q2：能不能 headless？**

不建议。无头模式更容易被风控，部分站点渲染也不完整。
服务器上用 Xvfb 提供一个「有头」的虚拟显示更稳。

**Q3：能不能多线程/多进程？**

同一个 Firefox profile 只能被一个进程使用。要多并发就多开 profile、
多装实例，并注意目标站的频率限制。反爬站点通常不建议高并发。

**Q4：cookie 能不能导出给 requests 用？**

这类站点的 cookie 与浏览器 JS 环境绑定，导出回放大概率失效。
老老实实让浏览器发请求，或者只把浏览器当「取数通道」，不要试图全量 HTTP 化。

**Q5：为什么不用 undetected-chromedriver / stealth 插件？**

它们主要处理 `navigator.webdriver`、UA、指纹等「静态特征」，
但本文的问题是 **Debugger 协议本身**。只要 CDP Debugger 还开着，
再 stealth 也没用。

**Q6：还有哪些站点会这样？**

凡是「正常浏览器 200、Playwright/DP 400、F12 也 400」的站点，
都建议先做一次 Debugger 对照实验。瑞数、部分金融/政务站、
以及一些使用同类 JS 挑战的站点都可能命中。

## 十八、总结

1. **412/400 不一定是 cookie 或签名问题**，先做「浏览器驱动方式」的对照实验。
2. 最小 CDP 客户端 + 按域 enable，是最快定位手段。**只有 Debugger 挂 = 石锤**。
3. 原理是 `debugger;` 的语义被调试器改变，计时/调用栈异常，挑战结果被静默作废。
4. 解决思路不是「更努力地逆 JS」，而是**换一个没有 Debugger 通道的协议**：
   Firefox + WebDriver BiDi。
5. 工程落地注意四件事：选择器翻译、动作链逐条 `perform`、`Keys.ENTER`、
   `wait="interactive"`。
6. 最后，风控是「协议 + 指纹 + 频率 + 行为」的组合。协议过了，也别猛刷。
